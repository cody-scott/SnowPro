## Hierarchy

```
Organization
 └── Account
      ├── Users, Roles, Warehouses, Resource monitors,
      │   Integrations, Network policies, Shares   (account-level objects)
      └── Database
           └── Schema
                └── Tables, Views, Stages, File formats, Sequences,
                    Pipes, Streams, Tasks, UDFs, Stored procedures,
                    Dynamic tables, ML models, ...      (schema-level objects)
```

- **Organization** — groups your accounts; managed with the **ORGADMIN** role (or the organization account). Used for creating accounts, org-wide usage views, replication between accounts.
- Fully-qualified name: `database.schema.object`.
- **Applications** (Native Apps) are installed at the account level.

## Database objects to know

| Object | Notes |
|---|---|
| **Stage** | Location of files. **User** stage `@~`, **table** stage `@%table`, **named** stage `@name` (internal or external). |
| **File format** | Reusable definition of how to parse files (CSV, JSON, Parquet, Avro, ORC, XML). |
| **View** | Standard, materialized, secure (see 1.5). |
| **UDF** | Called in SQL expressions, returns a value (scalar) or rows (UDTF). Languages: SQL, JavaScript, Python, Java, Scala. |
| **Stored procedure** | Invoked with `CALL`, can run DDL/DML and procedural logic. Runs with **owner's rights** (default) or **caller's rights** (`EXECUTE AS CALLER`). |
| **Pipe** | Wraps a `COPY INTO` statement for **Snowpipe**. |
| **Share** | Named object that grants read access to database objects to consumer accounts. |
| **Sequence** | Generates unique numbers. Values are unique but **not guaranteed gap-free**. |
| **ML model** | Model versions stored in the Snowflake **Model Registry**. |
| **Application** | An installed **Native App**. |

> **Owner's vs caller's rights:** An owner's-rights procedure lets a caller with only `USAGE` on the procedure act on objects the owner can access — the classic exam scenario. Switch to `EXECUTE AS CALLER` to require the caller's own privileges.

## Parameters, hierarchy and precedence

Three kinds: **account**, **session**, **object** parameters.

- Session parameters: **Account → User → Session**. The most specific wins: a value set with `ALTER SESSION` beats the user default, which beats the account default.
- Object parameters: **Account → Database → Schema → Table** (e.g. `DATA_RETENTION_TIME_IN_DAYS`). A lower-level setting overrides the inherited one.
- Inspect with `SHOW PARAMETERS [IN SESSION | IN ACCOUNT | IN TABLE t]`; the `level` column shows where a value was set.

## Context

Each session has a current **role, warehouse, database, schema** — set with `USE ROLE`, `USE WAREHOUSE`, etc. Context functions: `CURRENT_ROLE()`, `CURRENT_WAREHOUSE()`, `CURRENT_DATABASE()`, `CURRENT_SCHEMA()`, `CURRENT_USER()`, `CURRENT_ACCOUNT()`, `CURRENT_REGION()`.
