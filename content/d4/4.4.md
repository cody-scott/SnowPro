## Structured, semi-structured, unstructured

| Kind | Examples | In Snowflake |
|---|---|---|
| **Structured** | Rows and columns with a fixed schema | Regular typed columns |
| **Semi-structured** | JSON, Avro, ORC, Parquet, XML: nested, no fixed schema | **VARIANT**, **OBJECT**, **ARRAY** (and typed *structured* ARRAY / OBJECT / MAP columns) |
| **Unstructured** | Images, PDFs, audio, video, documents | Files on a **stage**, accessed by URL or a **FILE** value |

## Semi-structured data

- **VARIANT** holds any value, including an OBJECT or ARRAY. An **OBJECT** is a set of key-value pairs (like a map/dictionary); an **ARRAY** is a list. Values inside OBJECT and ARRAY are VARIANTs.
- Load JSON into a VARIANT column, or into typed columns with `MATCH_BY_COLUMN_NAME` / a COPY transformation (see 3.1). Convert strings with **`PARSE_JSON`** (`TRY_PARSE_JSON` returns NULL instead of failing).
- **Traverse paths:** `src:customer.name` (a colon for the first level, then **dot** notation) or `src['customer']['name']` (**bracket** notation). Array elements: `src:items[0]`.
- **The column name is case-insensitive, but element names are case-sensitive.** `src:Name` and `src:name` are different.
- Path results are VARIANT. **Cast** to use them as normal values: `src:price::NUMBER`, `src:name::STRING` (without a cast, strings come back in double quotes).
- `TYPEOF(v)` returns the type inside a VARIANT.

### FLATTEN

- **`FLATTEN`** is a **table function** that turns each element of an ARRAY or OBJECT into **its own row**. Use it with **`LATERAL`** (or `TABLE(...)`) to join each row to its exploded elements.
- Output columns: **`SEQ`, `KEY`** (object keys), **`PATH`, `INDEX`** (array position), **`VALUE`** (the element), **`THIS`**.
- Options: `INPUT =>` (required), `PATH =>` (flatten a nested element), **`OUTER => TRUE`** (keep rows whose array is empty or missing, like a left join), **`RECURSIVE => TRUE`** (flatten all nested levels), `MODE => 'OBJECT' | 'ARRAY' | 'BOTH'`.

```sql
SELECT o.src:order_id::NUMBER AS order_id,
       i.value:sku::STRING    AS sku,
       i.value:qty::NUMBER    AS qty
FROM orders o,
     LATERAL FLATTEN(INPUT => o.src:items) i;
```

- Build semi-structured values with `OBJECT_CONSTRUCT`, `ARRAY_CONSTRUCT`, and aggregate them with **`ARRAY_AGG`** / `OBJECT_AGG`.

## Unstructured data

- Store files on an **internal or external stage**; a **directory table** lists them (see 3.1).
- **Three URL types:**

| URL | Built with | Access |
|---|---|---|
| **Scoped URL** | `BUILD_SCOPED_FILE_URL` | Temporary (expires with the result cache, **24 h**); no stage privilege needed; usage is logged. Good for giving access through a view or share |
| **File URL** | `BUILD_STAGE_FILE_URL` or the directory table | **Permanent**; the caller needs privileges on the stage |
| **Pre-signed URL** | `GET_PRESIGNED_URL` | Plain HTTPS link; **no Snowflake login**; expires after a time you set. For BI tools and browsers. Internal stages need `SNOWFLAKE_SSE` encryption |

- **Process** files with Java / Python **UDFs and procedures** (read the file in handler code), the **FILE** data type (`TO_FILE`), or **Cortex AI functions** such as **`AI_PARSE_DOCUMENT`** (text and layout extraction) and other AI SQL functions (see 1.6).

## Aggregate functions

- **Aggregate** functions take many rows and return **one row per group**: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `MEDIAN`, `COUNT_IF`, `LISTAGG` (concatenate strings), `ARRAY_AGG`.
- `HAVING` filters groups after aggregation (`WHERE` filters rows before it).
- **`GROUP BY ROLLUP`** adds subtotals up a hierarchy plus a grand total; **`CUBE`** adds all combinations; **`GROUPING SETS`** chooses specific groupings.
- **Approximate** functions are faster on huge data, at the cost of a small error: **`APPROX_COUNT_DISTINCT`** (alias for **`HLL`**, HyperLogLog), `APPROX_PERCENTILE`, `APPROX_TOP_K`.
- `PIVOT` turns unique row values into columns (with an aggregate); `UNPIVOT` does the reverse.

## Window functions

- A **window function** computes a value **for every row** using a set of related rows (the window). Unlike an aggregate, it **doesn't collapse rows**.
- Syntax: `fn(...) OVER (PARTITION BY ... ORDER BY ... [window frame])`.
  - `PARTITION BY`: the groups (like GROUP BY, but rows stay).
  - `ORDER BY`: order inside each partition; needed for ranking and running totals.
  - **Window frame**: e.g. `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` for moving averages.
- **Ranking:** `ROW_NUMBER` (1, 2, 3, 4), `RANK` (1, 2, 2, 4: gaps after ties), `DENSE_RANK` (1, 2, 2, 3: no gaps), `NTILE`, `PERCENT_RANK`, `CUME_DIST`.
- **Offset:** `LAG` (previous row), `LEAD` (next row), `FIRST_VALUE`, `LAST_VALUE`.
- **Aggregates as windows:** `SUM(x) OVER (PARTITION BY ...)` for totals per group on every row; add `ORDER BY` for a running total.
- **`QUALIFY`** filters on window function results, the way `HAVING` filters on aggregates. Order of evaluation: FROM → WHERE → GROUP BY → HAVING → window functions → **QUALIFY** → DISTINCT → ORDER BY → LIMIT.

```sql
-- Latest order per customer
SELECT * FROM orders
QUALIFY ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_ts DESC) = 1;
```

## Writing SQL that performs well

- **Select only the columns you need.** Storage is columnar, so only referenced columns are scanned; `SELECT *` reads them all.
- **Filter early and selectively** so micro-partitions are pruned. Avoid wrapping filter columns in functions or casts, and avoid `LIKE '%text'` with a leading wildcard (or add search optimization).
- **Use `UNION ALL`** unless you need duplicates removed (`UNION` adds an aggregation step).
- **Always give join conditions** and check join keys for duplicates to avoid exploding joins.
- Use **`QUALIFY`** for top-N-per-group instead of self-joins or nested subqueries.
- Use **approximate functions** (`APPROX_COUNT_DISTINCT`) when an exact count isn't needed.
- Check the **Query Profile** and query insights after changes (see 4.1).
