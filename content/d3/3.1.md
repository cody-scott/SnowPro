## Loading options at a glance

| Method | Source | Compute | Typical latency |
|---|---|---|---|
| **Bulk `COPY INTO <table>`** | Files in a stage | **Your virtual warehouse** | Whenever you run it |
| **Snowpipe** | Files in a stage | Serverless | About a minute after Snowpipe learns of a file |
| **Snowpipe Streaming** | Rows from an SDK, REST API or the Kafka connector (no files) | Serverless | As low as ~5 seconds |
| **Snowsight load wizard** | Local files (up to **250 files, 250 MB each**) | Your warehouse | Manual |

Each bulk `COPY` statement runs in **a single transaction**. 3.2 covers Snowpipe and Snowpipe Streaming.

## File formats

- `TYPE` = **CSV** (the default), **JSON**, **AVRO**, **ORC**, **PARQUET**, **XML**.
- **Unloading** supports only **CSV, JSON and Parquet**. XML is load-only, and JSON unloads only from VARIANT columns.
- A **named file format** (`CREATE FILE FORMAT`) is a schema object you can reuse in stages, `COPY` statements and external tables. Options set directly in a `COPY` statement override the ones on the stage or table. Snowflake recommends setting **copy options** (such as `ON_ERROR`) in the `COPY` command, not on the stage.
- CSV options to know: `FIELD_DELIMITER` (default `,`), `SKIP_HEADER`, `PARSE_HEADER`, `FIELD_OPTIONALLY_ENCLOSED_BY`, `NULL_IF`, `EMPTY_FIELD_AS_NULL`, `ERROR_ON_COLUMN_COUNT_MISMATCH`, `TRIM_SPACE`, `ENCODING` (default **UTF-8**).
- JSON options: `STRIP_OUTER_ARRAY` (removes the outer `[ ]` so each element becomes a row) and `STRIP_NULL_VALUES`.
- `COMPRESSION = AUTO` detects gzip, bz2, brotli, zstd, deflate and raw deflate.

```sql
CREATE FILE FORMAT my_csv TYPE = CSV SKIP_HEADER = 1 FIELD_OPTIONALLY_ENCLOSED_BY = '"' NULL_IF = ('', 'NULL');
```

## Stages

A **stage** is where data files live for loading and unloading.

| Stage | Reference | Notes |
|---|---|---|
| **User** | `@~` | One per user, created automatically. Only that user's files. **Can't alter or drop**; **no file format options** (put them in `COPY`). |
| **Table** | `@%mytable` | One per table, created automatically. Many users, but loads **one table** only. **Not a separate object**: no grantable privileges, you must **own the table**. Can't alter or drop; **doesn't support COPY transformations**. Iceberg tables have no table stage. |
| **Named internal** | `@mystage` | Schema object. Many users and tables, privileges can be granted. Recommended for regular loads. |
| **Named external** | `@myext` | Schema object that points to **S3, GCS or Azure** (any cloud, whatever cloud hosts your account). Stores the URL, credentials or a **storage integration**, and format options. |

- **`PUT`** uploads local files to an **internal** stage only (it auto-compresses with **gzip** by default, `AUTO_COMPRESS = TRUE`). **`GET`** downloads from an **internal** stage only. For external stages, use the cloud provider's tools.
- `LIST @stage` shows files; `REMOVE @stage/path` deletes them.
- Data in **archival storage classes** (such as S3 Glacier Flexible Retrieval or Deep Archive) can't be read.
- You can query staged files directly: `SELECT $1, $2, METADATA$FILENAME FROM @stage (FILE_FORMAT => 'my_csv')`.

### Server-side encryption

**Internal stages** (`ENCRYPTION = (TYPE = ...)`, can't be changed after creation):

| Type | Meaning |
|---|---|
| `SNOWFLAKE_FULL` (**default**) | Client-side encryption on `PUT` **plus** server-side AES-256. Required for **Tri-Secret Secure**. |
| `SNOWFLAKE_SSE` | **Server-side only**. Use it when people need **pre-signed URLs** or other direct access to unstructured files (otherwise downloaded files are unreadable). |

**External stages** describe how the files in your bucket are encrypted: `AWS_SSE_S3`, `AWS_SSE_KMS`, `AWS_CSE` (client-side, needs a `MASTER_KEY`), `GCS_SSE_KMS`, `AZURE_CSE`, or `NONE` (the default).

### Directory tables

- An **implicit object layered on a stage** (internal or external) that stores **file-level metadata**: path, size, last modified, ETag and a **Snowflake file URL**. No grantable privileges of its own.
- Enable with `DIRECTORY = (ENABLE = TRUE)` on `CREATE STAGE` or `ALTER STAGE`. Query with `SELECT * FROM DIRECTORY(@stage)`.
- Refresh **manually** (`ALTER STAGE ... REFRESH`) or **automatically** (`AUTO_REFRESH = TRUE`, driven by cloud event notifications). Auto-refresh overhead is billed as **Snowpipe** charges.
- Used for **unstructured data**: list files, join them to metadata tables, and build processing pipelines (streams can track a directory table, see 3.2).

## COPY INTO &lt;table&gt; (loading)

```sql
COPY INTO sales FROM @my_stage/2026/11/
  FILE_FORMAT = (FORMAT_NAME = 'my_csv')
  PATTERN = '.*sales_.*[.]csv[.]gz'
  ON_ERROR = 'SKIP_FILE';
```

- **Pick files** by path/prefix, `FILES = (...)` (up to **1,000** names, the fastest option) or `PATTERN` (regex, the slowest).
- **Simple transformations** with a `SELECT` over the stage: reorder, omit and cast columns, and truncate strings. **Not supported:** `WHERE`, `JOIN`, `GROUP BY`, `FLATTEN`, `ORDER BY`, `LIMIT`.
- `MATCH_BY_COLUMN_NAME = CASE_SENSITIVE | CASE_INSENSITIVE` loads columns by name (JSON, Avro, ORC, Parquet, CSV). It **can't be combined with a transformation `SELECT`**.
- **Schema detection:** `INFER_SCHEMA` plus `CREATE TABLE ... USING TEMPLATE` build a table from Parquet, Avro, ORC, JSON or CSV files.
- Other copy options: `PURGE = TRUE` (delete loaded files; failures are silent), `FORCE = TRUE` (reload everything, may duplicate), `SIZE_LIMIT`, `TRUNCATECOLUMNS` / `ENFORCE_LENGTH`, `RETURN_FAILED_ONLY`, `INCLUDE_METADATA`.

### Load metadata (no duplicates)

- Each table keeps **load metadata for 64 days**: file name, size, ETag, rows parsed, last load time, errors. `COPY` **skips files it has already loaded** that haven't changed.
- Files older than 64 days whose status is unknown are **skipped** by default. Load them with **`LOAD_UNCERTAIN_FILES = TRUE`** (still checks metadata) or **`FORCE = TRUE`** (ignores metadata and can duplicate rows).
- Snowpipe keeps **its own** load metadata (14 days, per pipe). Neither method sees the other's history.

### File sizing

- Aim for **100–250 MB compressed** per file. The number of parallel loads can't exceed the number of files.
- Split big files, combine many tiny ones. A larger warehouse helps only when there are enough files to spread across it.

## Error handling

| `ON_ERROR` | Behavior |
|---|---|
| **`ABORT_STATEMENT`** | **Default for bulk COPY.** Stop the whole load at the first error. |
| `CONTINUE` | Load the good rows and skip the bad ones. |
| `SKIP_FILE` | **Default for Snowpipe.** Skip any file that has an error (buffers the whole file, so it's slower). |
| `SKIP_FILE_n` / `'SKIP_FILE_n%'` | Skip a file once its error rows reach a count or exceed a percentage. |

- **`VALIDATION_MODE`** tests files **without loading**: `RETURN_n_ROWS`, `RETURN_ERRORS`, `RETURN_ALL_ERRORS`. It **doesn't work with transformations** (or Iceberg tables).
- **`VALIDATE(table, JOB_ID => '_last')`** returns errors from a past `COPY`. It returns nothing for loads that used `ABORT_STATEMENT`.
- **Error logging** (`ALTER TABLE t SET ERROR_LOGGING = TRUE`) records rejected rows in the table's **error table**, where you can query, fix and reload them. Which rows get recorded depends on `ON_ERROR` (every row with `CONTINUE`, one per file with `SKIP_FILE`, none with `ABORT_STATEMENT`).
- **History:** `INFORMATION_SCHEMA.COPY_HISTORY` / `LOAD_HISTORY` (**14 days**) and `ACCOUNT_USAGE.COPY_HISTORY` (**365 days**, up to ~2 h latency). Snowsight: **Monitoring → Copy History**.

## COPY INTO &lt;location&gt; (unloading)

```sql
COPY INTO @my_stage/export/sales_
  FROM (SELECT * FROM sales WHERE year = 2026)
  FILE_FORMAT = (TYPE = PARQUET) HEADER = TRUE MAX_FILE_SIZE = 104857600;
```

- Unload a table or **any query** to an internal or external stage (or straight to a cloud URL). Then `GET` (internal) or use cloud tools to download.
- Output is split into **multiple files in parallel** by default. **`MAX_FILE_SIZE`** defaults to **16 MB** (maximum **5 GB** on cloud storage). **`SINGLE = TRUE`** writes one file.
- `PARTITION BY <expr>` writes files into folders by value. `HEADER = TRUE` includes column names. `OVERWRITE`, `INCLUDE_QUERY_ID` (unique file names; the recommended way to avoid duplicates) and `DETAILED_OUTPUT` (one result row per file).
- **Formats:** CSV (default, gzip-compressed), JSON (VARIANT columns only), Parquet.
- `NULL_IF`, `EMPTY_FIELD_AS_NULL` and `FIELD_OPTIONALLY_ENCLOSED_BY` keep NULLs and empty strings distinguishable.

> **Exam tip:** "Upload from a laptop" → `PUT` to an **internal** stage. "Check files for errors without loading" → `VALIDATION_MODE`. "Reload an unchanged file" → `FORCE = TRUE`. "Load one table, files shared by many users, no extra objects" → **table stage**.
